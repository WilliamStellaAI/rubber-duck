# rubber-duck-handoff · 会话落盘

## 目标

把长会话里**易被压缩丢掉**的拍板与坑位写入仓库，让新会话不依赖聊天记忆。

默认路径：`docs/session-handoff.md`（没有则创建）。若已有 `docs/compass.md`（旧误称），迁移内容到 `session-handoff.md` 并删除或改为指向新文件的一行说明。

由 `rubber-duck` rule 在触发时路由至此；本 skill **按需读取**，不要做成 always-on rule。

## 被调用时怎么做

1. **先读**现有落盘文档（若有），并浏览 `docs/project-progress.md`、`docs/deferred-backlog.md`、`docs/known-issues.md`（有则读）。
2. **收集增量**：本会话用户拍板（含「不要/改为/撤掉」）、`git log -15 --oneline`、未提交的高信号改动。
3. **更新落盘文档**：合并，禁止盲目整文件覆盖。仍有效的决策保留；过时项删除或标「已废弃/已撤回」，并在修订记录说明。
4. **保持短**：多用表格；不贴整段 transcript。细节链到其他 docs。
5. **回复用户**：写明更新了哪个路径、最重要的 3 条变更。**除非用户要求，否则不 commit。**

## 必备章节（没有就建）

1. 一句话现状  
2. 已拍板决策（勿轻易推翻）— 表格  
3. 方法论 / 设想 vs 落地（相关时再写）  
4. 高价值坑  
5. 进行中 / 下一步 — 勾选列表  
6. 关键路径速查  
7. 修订记录 — 日期 + 一行说明  

## 写作规则

- 记**决策与不变量**，不要记每一次 UI 微调。  
- 优先写清：「选了什么 / 明确不做什么」。  
- 试过又撤的方案要标出来。  
- **禁止**写入密钥、token、签名 URL。  
- 项目文档是中文则用中文写。  
- 不使用已废弃的「罗盘 / compass」指称落盘。

## 反模式

- 粘贴整段聊天摘要。  
- 把 `project-progress.md` 全文再抄一遍。  
- 每个错别字/小样式都改落盘文档。  
- 声称「还记得」未写入落盘文档/git/docs 的口头细节。

## 与硬闸的关系

落盘**不代替授权**。排障时下一步若是「改代码」，须已获用户「修 / 开干」；未授权前禁止换库、换架构、大改呈现——即使已写入落盘也不行。查/说根因可以写进落盘；改实现必须先过硬闸（见 `rubber-duck-troubleshoot`）。
